海外开发者到底在推荐什么 · 中文导读

169,666 个条目 · 747,589 次提及 · 数据截至 2026-08-21

这份榜单抓的是 Hacker News——全球做技术、做产品的人最集中的地方，二十年没变。 我把 2006 年至今 4930 万条记录全下下来，找出被不同的人反复推荐的链接， 按推荐人数排序。每一条都能点回原评论。

先给结论，五条：

1. 他们最爱的「视频」不是教程，是演讲。排在前面的几乎没有「教你写代码」， 而是「某个东西为什么是这样」——语言设计、系统原理、行业史。

2. 工具榜比 Star 榜诚实。GitHub 星数可以刷、可以靠发布时间堆， 但「不同的人在无关的帖子里反复贴同一个仓库」刷不出来。这个榜上全是真在用的东西。

3. 论文榜意外地「实用」。不是最前沿的，是能被工程师拿去用的——系统、编译器、模型行为分析。

4. 书榜偏「改变思维方式」，不偏技术书。排前面的多是心理学、决策、组织， 而不是某个框架的权威指南。

5. 一个信号：同一个东西被同一个人反复提，只算一次。所以榜单尾部那些「1 人推荐」， 其实说明它只火过一次——那不算品味，那叫运气。

这些数据怎么来的

数据源是完整的 Hacker News 存档（2006-10 至今，按月的 parquet）。流程四步： 抽出每条评论里的外链 → 用评论里的锚文本当标题（没有锚文本的再去 YouTube／iTunes／ Steam／Open Library／arXiv 查）→ 按 ID 归一（ASIN、arXiv 号、IMDb tt、Steam appid、 GitHub 仓库）→ 用关键词 + 模型判定「这条评论是在推荐，还是只是提到」。 排名只认不同的人，不认次数。

已知短板：只收带链接的推荐。有人只写书名不贴链接，我们抓不到——所以书榜偏弱， 电影／游戏／播客样本太少，已经挪到 Other 里去了。视频、工具、论文三类不受影响。 完整方法与误差写在 method 页。
